# CEC for apps, stage 4a: minimal playback device (2026-11-14)

**Status: verified on a board 2026-11-14 (see "Bench result" at the
end).** The record above the bench result was written before that run and
is left as written:

**Status when written: built and host-tested, not run on a board.** Nothing below is a
hardware result yet. The bench steps at the end say what to run and what a
pass looks like.

## What was built

- `bsp/cec/cec.{c,h}`: start/stop, physical address (default `0x1000`), the
  task, polled events (key down/up, standby, active source, address), One
  Touch Play and standby to the TV, counters. The pin (GPIO31 open drain),
  the TIMER1 alarm, both interrupt handlers and the send and event queues are
  in C.
- `bsp/cec/fwCECWire`, `fwCECCore`: the stock firmware's CEC bit engine and
  device, copied unchanged (C++). `cec_engine.{h,cpp}` is the C entry point
  to them, with the layouts of the shared structs checked at compile time.
- `apps/hello_cec`: colour bars on the TV (so the selected input shows
  something), the claimed address, each remote key, standby and input changes
  and the timing counters over RTT and on the LCD; the remote's arrows move a
  square; GREEN wakes the TV and selects this input, RED puts the TV in
  standby.
- Host tests: `tests/test_cec_{main,wire,controller,rx_queue,key_hold}.cpp`
  (the firmware's CEC tests, ported unchanged except the harness file name:
  79 tests, 1,792,078 checks, 0 failures on Windows MinGW GCC; the bit engine
  is run on a simulated wire with handler delays up to 160 µs) and
  `tests/test_cec_engine.c` (the C entry points: claim, name, keys and the
  550 ms key timeout, standby in, One Touch Play, standby out, Inactive
  Source at stop, engine send/cancel).

## What rests on what

| Claim | Basis |
|---|---|
| The bit engine meets the standard's timing with handlers up to ~160 µs late | Host simulation (ported test), and the stock firmware's bench runs; not run with this BSP |
| GPIO31 is the CEC wire on father board rev 2, open drain, board pull-up | Owner's confirmation 2026-11-11 and the schematic notes (see the stage 0 findings, `2026-11-14-cec-pin-release-e2e.md`) |
| A TV switches input and wakes on One Touch Play from this device | Stock firmware bench behaviour with the same device code; not run here |
| CEC works with the NFC board mated (`NFC_RFQ` shares the net) | Stock firmware bench note; not tried with this BSP |

**UNVERIFIED HW:**

- Everything on the wire: claim, keys, standby, wake. No board run yet.
- Interrupt lateness in a BSP app next to the colour-bar picture. The bars use
  no interrupt, so lateness should come only from the app; unmeasured.
- TIMER1 counting microseconds in a BSP app: the SDK's runtime start-up
  starts every tick generator, and `cec_start()` refuses if a 200 µs busy wait
  does not read 150-250 µs on TIMER1. The check has not run on a board.
- CEC state left by the stock firmware when it launches the app (its GPIO31
  edge enables, a TIMER1 alarm, the wire possibly pulled low): `board_init()`
  makes GPIO31 an input with no pull, and `cec_start()` clears GPIO31's
  latched edges before enabling its own. Whether an alarm or NVIC enable from
  the firmware survives into the app was not checked.
- Physical address `0x1000` is right only on TV input 1. On another input
  `cec_wake_tv()` names the wrong input in `<Active Source>`.
- Which power rail feeds the CEC pull-up and whether any rail must be on for
  the wire to work was not read from the schematic; the app declares only
  the `DISPLAY` zone, like `hello_tvout`.

## Bench steps (owner)

1. `fw install-app hello_cec.uf2` (or `fw ramrun hello_cec`), TV on its
   input 1 with CEC enabled in the TV's settings, launch, `fw rtt`.
2. Pass: `address: 4 (1.0.0.0)` (or 8 or 11) within about a second; the TV's
   input or device list shows "FW2 hello_cec".
3. Press GREEN with the TV on another input or in standby: the TV turns on and
   shows the colour bars; `TV switched to this input`.
4. Press the TV remote's arrows, OK and colour keys: each prints `key down:`
   and `key up:` with its name; the arrows move the yellow square.
5. Switch the TV off with its own remote: `TV went to standby`. Press RED with
   the TV on: the TV goes to standby.
6. Throughout: `late aborts 0 rx dropped 0 PASS`.

## Bench result, 2026-11-14 (owner, FreeWili 2, TV on input 1 with CEC on)

`hello_cec` passed: the TV listed the device; the TV remote's arrows moved the square; the TV
switched off with its own remote gave `TV went to standby`; GREEN turned the TV on and switched
it to this input. Receiving and sending on the CEC wire from a BSP app are verified.
